# Важные дела

Основа приложения для личной продуктивности: Django и PostgreSQL.
Сервер подключен к базе данных с пользователями и задачами.

## Данные пользователя

Используем готовую модель `User`, чтобы не писать собственную систему.

| Поле | Что хранит |
| --- | --- |
| `id` | Уникальный номер, назначается автоматически. |
| `username` | Уникальный логин. |
| `email` | Электронную почту. |
| `password` | Хеш пароля; сам пароль в базе не сохраняется. |
| `date_joined` | Дату регистрации, назначается автоматически. |

Django также содержит стандартные поля имени, фамилии, последнего входа
и служебные признаки доступа. Своих дополнительных полей не добавляем.
Регистрацию, вход через сайт и обязательность почты настроим отдельным шагом.

## Данные задачи

Модель `Task` описывает, что хранится о каждой задаче:

| Поле | Что хранит |
| --- | --- |
| `id` | Уникальный номер, назначается автоматически. |
| `title` | Название задачи, до 200 символов. |
| `owner` | Ссылку на пользователя, которому принадлежит задача. |
| `created_at` | Дату и время создания, назначаются автоматически. |
| `completed_at` | Дату и время выполнения; пустое значение означает, что задача открыта. |

Отдельного поля статуса нет: открытые задачи выбираются по пустой дате
выполнения, завершенные — по заполненной. При удалении пользователя через
Django удаляются и его задачи. Проверку доступа к задачам добавим вместе
с обработкой запросов; сама связь с владельцем не заменяет проверку прав.

## Что за файлы

| Файл | Для чего нужен |
| --- | --- |
| `manage.py` | Запуск сервера и служебных команд Django. |
| `config/settings.py` | Настройки сервера и подключения к базе. |
| `config/urls.py` | Адреса будущих страниц; пока список пустой. |
| `config/wsgi.py` | Подключение Django к веб-серверу. |
| `tasks/models.py` | Описание полей задачи и связи с пользователем. |
| `tasks/migrations/` | Созданные Django инструкции изменения таблиц задач. |
| `requirements.txt` | Библиотеки с закрепленными версиями. |
| `compose.yaml` | Запуск PostgreSQL в Docker и хранение данных. |
| `.env.example` | Образец локальных настроек. |
| `setup.sh` | Подготовка окружения и проверка соединения. |

Пустой `config/__init__.py` позволяет Python использовать папку как модуль.
`.gitignore` исключает из Git пароли и установленные библиотеки.

## Подготовка

Нужны Python 3.12+ и запущенный Docker с Compose. Из папки проекта:

```bash
bash setup.sh
```

Скрипт устанавливает библиотеки в `.venv`, при первом запуске создает
закрытый файл `.env` со случайными ключом Django и паролем базы,
запускает PostgreSQL, создает или обновляет таблицы командой `migrate`
и проверяет соединение. Повторный запуск сохраняет существующие настройки
и данные. Миграции — сохраненные изменения структуры базы; стандартные
миграции пользователей уже входят в Django, а миграция задач хранится
в `tasks/migrations/`.

## Запуск после подготовки

```bash
docker compose up -d --wait
.venv/bin/python manage.py runserver 127.0.0.1:8000
```

Пока отображается стандартная стартовая страница Django. Таблицы пользователей,
прав доступа и задач созданы. Интерфейс и действия с задачами через сайт
добавим на следующих согласованных этапах.

Остановка: `Ctrl+C` для Django и `docker compose stop` для PostgreSQL.
Данные находятся в Docker-хранилище `postgres_data` и сохраняются при
перезапуске контейнера. Удаление хранилища удалит и данные.

Это окружение разработки: база и сервер доступны только на текущей машине.
Публикацию в интернете и резервное копирование настроим отдельным шагом.
